## 1. 目的与范围

本报告仅服务于 `D:\自制软件\thesis\验证推演3.15` 下的独立推演与验证，不修改论文正文。目标是把下面五件事分开验证：

1. 连续满载集合 `S_N = {1,2,...,N}` 是否存在解析最优解；
2. `tau` 判据是否可改写为解析最优点附近的平台存在性与平台宽度判据；

4. `N = 9` 可行而 `N = 10` 不可行，是否可由解析边界直接推出；
5. 即使连续满载特例可解析，MIS 对一般非连续集合是否仍有独立价值。

## 3. 共享数学口径

验证脚本直接复用了 `tools/plot_smin.py` 中的 `k_from_lr`、`positions_for_k`、`smin_for_lr` 等函数，确保与论文现有绘图口径一致。

在连续满载特例 `S_N = {1,2,...,N}` 下，有

```math
s_{\min}(k) = \min_{1 \le d \le N-1} \| d k \|
```

其中 `||x||` 表示到最近整数的距离。

数值扫描与解析推导共同支持下面的结论：

```math
s_{\min}^{\max} = 1/N
```

且当

```math
k^* = m/N,\quad \gcd(m,N)=1
```

时精确达到；对应几何比为

```math
(L/R)^* = \sin^2(\pi m/N).
```

## 4. 结果一：连续满载问题确有 closed-form benchmark

脚本：`01_verify_continuous_analytic_optimum.py`

验证了 `N = 9, 10, 30, 50, 100` 五组连续满载问题。数值扫描得到的全局峰值与解析值 `1/N` 的误差都在 `1.0e-6` 量级。

关键结果如下：

| N | numeric peak `s_min` | analytic peak `1/N` | matched family `m/N` | `|error|` |
|---|---:|---:|---:|---:|
| 9   | 0.111109888900 | 0.111111111111 | 4/9   | 1.22e-06 |
| 10  | 0.099998600000 | 0.100000000000 | 3/10  | 1.40e-06 |
| 30  | 0.033332200000 | 0.033333333333 | 7/30  | 1.13e-06 |
| 50  | 0.019998920000 | 0.020000000000 | 11/50 | 1.08e-06 |
| 100 | 0.009998960000 | 0.010000000000 | 23/100| 1.04e-06 |

解释：

- 不同 `m/N` 分支的峰高相同，均为 `1/N`；
- 图上看到的是同一最优家族的不同可见分支，而不是“有的解析最优高、有的低”；
- 随 `N` 增大，峰高按 `1/N` 衰减，景观会更碎，但连续满载特例仍然可解析。

## 5. 结果二：`tau` 判据可直接改写为平台存在性判据

记

```math
\delta = \tau_0 / \mathcal{F}.
```

则对连续满载特例，解析最优峰高固定为 `1/N`，于是平台存在条件立刻变成：

- 若 `1/N > delta`，则存在非零平台；
- 若 `1/N = delta`，则平台退化为点；
- 若 `1/N < delta`，则即使取解析最优点也无法满足判据。

这意味着，`tau` 在连续满载问题中不只是“横线”，而是：

1. 判定该 `N` 是否可实现；
2. 判定解析最优附近是否还有工艺裕度；
3. 决定平台宽度。

这与 `M_max = floor(F / tau0)` 是一致的：对连续满载问题，它不仅是上界，而且是实际可达的容量边界。

## 6. 结果三：局部平台公式与细步长数值扫描高度一致

脚本：`02_verify_platform_formula.py`

对 `N = 9` 的三个解析峰族 `m = 1, 2, 4`，验证了局部平台公式与高分辨率数值扫描的一致性。

若 `a` 是 `m` 关于模 `N` 的逆元，即 `a m ≡ 1 (mod N)`，则当 `delta < 1/N` 时，

```math
k \in \left[k^* - \frac{1/N - \delta}{a},\ k^* + \frac{1/N - \delta}{N-a}\right]
```

给出了该解析峰附近满足 `s_min >= delta` 的局部区间。再通过

```math
L/R = \sin^2(\pi k)
```

即可映射到几何比平台。

在 `F = 29.8, tau0 = 3, delta = 0.100671140940` 下：

| branch | analytic LR interval | numeric LR interval | max abs error |
|---|---|---|---:|
| `m = 1` | [0.096734412339, 0.119625903818] | [0.096734821260, 0.119625401660] | 5.02e-07 |
| `m = 2` | [0.406723596973, 0.421262187814] | [0.406724350171, 0.421261435350] | 7.53e-07 |
| `m = 4` | [0.968223187052, 0.975201427729] | [0.968223379160, 0.975201198025] | 2.30e-07 |

结论：局部平台公式与细步长数值扫描在 `L/R` 上的误差都落在 `1e-6` 量级，可视为已经非常充分地数值确认。

## 7. 结果四：当前 9 模实验点确实落在解析最优附近的平台内

脚本：`03_n9_experiment_platform_check.py`

采用参数：

- `N = 9`
- `m = 2`
- `R = 25.0 mm`
- `L_nom = 10.25 mm`
- `L_nom / R = 0.410`
- `tau0 = 3`

### 7.1 名义设计精细度 `F = 29.8`

- `delta = 3 / 29.8 = 0.100671140940`
- 解析最优：
  - `k^* = 2/9 = 0.222222222222`
  - `(L/R)^* = sin^2(2*pi/9) = 0.413175911167`
  - `L^* = 10.329397779 mm`
- 解析平台：
  - `L/R in [0.406723596973, 0.421262187814]`
  - `L in [10.168089924, 10.531554695] mm`
- 当前名义点：
  - `L/R = 0.410000000000`
  - `s_min = 0.105975558257`
  - `tau_eff = F * s_min = 3.158071636066`
  - 相对解析峰偏差：`-0.079397779 mm`
  - 距左边界裕度：`0.081910076 mm`
  - 距右边界裕度：`0.281554695 mm`

### 7.2 实测精细度 `F_exp = 31.35`

- `delta = 3 / 31.35 = 0.095693779904`
- 同一解析峰的解析平台扩大为：
  - `L/R in [0.403652974546, 0.425124989512]`
  - `L in [10.091324364, 10.628124738] mm`
- 当前名义点仍位于平台内部：
  - `tau_eff = 31.35 * 0.105975558257 = 3.322333751365`
  - 距左边界裕度：`0.158675636 mm`
  - 距右边界裕度：`0.378124738 mm`

结论：

1. 现有实验点不是“错点验证”；
2. 它位于解析最优 `L/R = sin^2(2*pi/9)` 附近的同一平台上；
3. 若以当前实测精细度回看，平台还会进一步变宽；
4. 因此实验结果更适合解释为“对解析最优附近平台鲁棒性的验证”，而不是对某个单点偶然命中的验证。

## 8. 结果五：9 模可行而 10 模不可行，可由解析边界直接推出

脚本：`04_n9_vs_n10_boundary.py`

在 `F = 29.8, tau0 = 3` 下，

- `delta = 0.100671140940`
- `1/9  = 0.111111111111 > delta`
- `1/10 = 0.100000000000 < delta`
- `1/11 = 0.090909090909 < delta`

因此：

- 连续 9 模满载可行；
- 连续 10 模满载即使取解析最优也不可行；
- `M_max = floor(29.8 / 3) = 9` 与这一解析边界完全一致。

这给出了“9 模成功、10 模失败”的一个非常直接而且干净的解释。

## 9. 结果六：MIS 对一般非连续集合仍然有独立价值

脚本：`05_mis_general_case_counterexamples.py`

为了避免把连续满载特例的解析性误解成“MIS 没有用了”，这里单独扫描了更一般的问题：

- 候选模式数：`N_scan = 15`
- 判据：`delta = 3 / 29.8`
- 比较三类容量：
  - 连续前缀 `1..M`
  - 任意连续区间
  - 任意子集的最大独立集 `MIS`

找到的反例如下：

| k | LR | MIS size | MIS set | best continuous prefix | best consecutive block |
|---|---:|---:|---|---:|---:|
| 0.052777777778 | 0.027240712200 | 8 | `1 3 5 7 9 11 13 15` | 1 | 1 |
| 0.061111111111 | 0.036408072717 | 8 | `1 3 5 7 9 11 13 15` | 1 | 1 |
| 0.469444444444 | 0.990813591724 | 8 | `1 2 5 6 9 10 14 15` | 2 | 2 |

结论：

- 连续满载特例可解析，并不意味着一般模式选择问题也可被连续结构覆盖；
- 当允许模式集合非连续时，MIS 能得到明显大于任意连续前缀或任意连续区间的容量；
- 因此更合理的论文分层应是：
  - 连续满载问题：解析解 + 平台裕度；
  - 一般非连续集合：MIS / 全局组合优化。

## 10. 哪些结论可安全写进论文

下面这些结论已经有清晰的公式和数值支持，可安全进入正文：

1. 对连续满载集合 `S_N = {1,...,N}`，`s_min` 最大值为 `1/N`，并在 `k = m/N, gcd(m,N)=1` 处达到；
2. 对应几何比为 `(L/R)^* = sin^2(pi m/N)`；
3. `delta = tau0 / F` 可作为连续满载问题的存在性与平台裕度判据；
4. 在 `F = 29.8, tau0 = 3` 下，连续 9 模可行，而连续 10 模不可行；
5. 当前名义实验点 `L/R = 0.410` 落在 `N = 9, m = 2` 的解析平台内，可视为近解析最优实现；
6. 对一般非连续集合，MIS 仍有独立价值，不应被连续满载解析解替代。

## 11. 哪些表述必须收紧

下面这些说法不建议继续原样使用：

1. “9 模最优设计必须依赖 MIS 搜索得到。”
   - 对连续满载特例，这一说法不成立。
2. “类分形自相似。”
   - 当前图和局部放大并不支持严格自相似。
3. “实验就是按 `L/R = sin^2(2*pi/9)` 设计的。”
   - 只有在历史设计过程确实如此时，才应这样写。
   - 若无法追溯设计记录，更稳的说法是：现有实验点与该解析设计目标高度一致，并落在同一平台内。

## 12. 当前最合理的论文叙事建议

在不立即改正文的前提下，当前最稳的结构判断是：

1. 保留 `tau` 作为中心判据；
2. 把连续满载 `1..N` 的设计问题单独提升为“可解析 benchmark”；
3. 把平台宽度解释为解析最优附近的工艺容差；
4. 把当前 9 模实验解释为解析平台内的工程验证；
5. 把 MIS 明确降为“一般非连续集合与一般工程约束”的扩展框架，而不是当前 9 模实验的唯一主解法。

## 13. 仍需保持谨慎的地方

以下判断目前已经很强，但在写入论文时仍应保持表述克制：

1. 本报告给出的平台公式已经与高分辨率数值扫描高度吻合，但论文中如果要把它作为正式命题，最好配一个简短推导；
2. 名义几何参数与最终交付件之间的偏差，目前仍主要靠实验表现反推，不宜把 `F` 的变化直接等价成几何尺寸偏差；
3. 如果后续要把“平台裕度”放进论文，最好再明确说明它描述的是理论几何容差窗口，而不是对制造误差来源的唯一解释。
